# Plan 01-02: Dashboard UI Dropdown Filters and Checklist Modal Integration

This plan implements the frontend layout, dropdown filters, and interactive modal overlay in the dashboard. It exposes sector filters, displays Luiz Barsi's defensive BESST indicators next to relevant stocks, and integrates the Checklist Modal overlay using native HTML5 accessibility standards.

<threat_model>
### Security Threat Model (ASVS Level 1)

1. **Cross-Site Scripting (XSS) (STRIDE: Tampering)**
   - *Threat*: A user submits a custom sector name containing HTML or `<script>` tags, causing arbitrary code execution when rendered in the dashboard or modal.
   - *Mitigation*: Ensure all dynamic texts (e.g. `asset.sector`, manual sector inputs) are rendered strictly inside standard React JSX text nodes (e.g. `<span>{asset.sector}</span>`). Never use `dangerouslySetInnerHTML` or direct DOM manipulation.
2. **Stale Component State (STRIDE: Spoofing / Tampering)**
   - *Threat*: Clicking "Checklist" for PETR4, then clicking "Checklist" for BBSE3, shows cached PETR4 data in the modal due to React component reuse without state reset.
   - *Mitigation*: Render the modal conditionally in `AssetRadar.tsx` using the `selectedTicker` state as a key or mount guard (e.g. `{selectedTicker && <ChecklistModal ticker={selectedTicker} onClose={...} />}`). This guarantees the component unmounts and remounts with fresh state when the active asset changes.
3. **Double Submission (STRIDE: Denial of Service)**
   - *Threat*: User repeatedly clicks "Salvar Checklist" before the backend database write finishes, causing multiple concurrent transactions and database lock contention.
   - *Mitigation*: Disable the save button and display a loading state (e.g. `isSaving`) during the active PUT request lifecycle.
</threat_model>
